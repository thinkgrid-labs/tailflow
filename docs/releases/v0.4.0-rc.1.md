# TailFlow v0.4.0-rc.1 (prerelease)

**This is an experimental release candidate for early testing. It is not
production-ready.** Several release checks have not been done yet (listed
below). The stable release on npm is still v0.3.3, and `npm install -g
tailflow` keeps installing it.

## Install

```bash
npm install -g tailflow@next         # the current release candidate
npm install -g tailflow@0.4.0-rc.1   # exactly this one
tailflow --version                   # tailflow 0.4.0-rc.1
```

Prebuilt binaries and `SHA256SUMS` are attached to this release.

### Going back to v0.3.3

**Remove the agent hooks first.** The hooks run the installed `tailflow`
binary. v0.3.3 does not know the hook command and exits with status 2, which
Claude Code and Codex treat as "block": every tool call would be refused.

```bash
tailflow agent uninstall claude                  # and/or: codex
tailflow agent uninstall claude --scope project  # if you installed with --scope project or local
npm install -g tailflow@latest                   # v0.3.3
```

If you already switched back, reinstall the candidate
(`npm install -g tailflow@0.4.0-rc.1`), run the uninstall commands, then
switch again. A project-scope hook (`.claude/settings.json`) that is
committed to a repository also affects teammates who run v0.3.3.

## What changed since v0.3.3

- **Durable history.** A local SQLite history (30 days / 2 GB by default)
  with redaction, capture modes and a completeness verdict on every response.
- **Agent capture.** Opt-in Claude Code and Codex hooks record sessions, tool
  calls, commands, reported file changes and subagents. Each hook states what
  it can and cannot see.
- **Agent dashboard.** Overview, sessions, activity search, a multi-agent
  timeline, files, commands and live logs. Updates arrive from a stream of
  committed events.
- **Independent evidence.** Opt-in file observation and Git snapshots are
  compared with what agents reported. Related evidence comes in five tiers
  and never claims cause.
- **Authenticated local API.** Clients use a per-run token; browsers use a
  one-time sign-in link.

The [changelog](https://github.com/thinkgrid-labs/tailflow/blob/main/CHANGELOG.md)
has the full list.

## Breaking changes

- **The HTTP API requires a credential.** v0.4.0 `tailflow-mcp` and
  `tailflow-logs` find the token by themselves. v0.3.x clients and plain
  `curl` get `401` and must send
  `Authorization: Bearer $(tailflow-daemon token)`.
- Without a credential, `/health` returns only `ok`, `version` and
  `auth_required`.
- `tailflow-logs` exits `4` when the daemon refuses the credential.
- `GET /api/v1/events?command=` is deprecated (use `program=`). Removal is
  planned for 0.5.

See [security](https://github.com/thinkgrid-labs/tailflow/blob/main/docs/security.md).

## Validated

- CI on Linux, macOS and Windows: formatting, Clippy, the full Rust test
  suite, the MSRV build (Rust 1.89) and resource checks.
- Web unit tests and browser end-to-end tests in Chromium, Firefox and WebKit,
  including accessibility checks.
- Platform smoke tests on Linux, macOS and Windows, including agent-hook
  install, capture and uninstall with synthetic hook input.
- SQLite schema migrations from earlier development schemas, and concurrent
  first opens of a new database.
- A documentation check of links, API routes, config keys and CLI flags
  against the built binaries.
- A live Codex 0.171 session on macOS: sessions, resume, subagents,
  `apply_patch`, token counts, spool replay and deduplication.

## Not yet validated

- **No 24-hour endurance run on Linux.** The longest runs are 8-hour soaks of
  earlier development builds.
- **No quiet-host benchmarks.** Nothing has been measured on a dedicated
  machine or on Linux or Windows, so no CPU or memory figures are published.
- **No real agent sessions on Windows.** Windows is covered only by CI with
  synthetic hook input.
- **Live Codex only on macOS.** Codex on Linux and Windows, and Codex's
  interactive `/hooks` trust review, are unconfirmed.

## Codex command outcomes

Codex sends no exit code for shell commands. A live 0.171 session sent only
the command's output. TailFlow therefore shows a Codex command's outcome as
`unknown`, never as success, and a failed Codex command looks the same as one
that worked.

Claude Code reports an exit code only when a command fails.

## Known issues

- Agent hooks report only what the agent tells them. Shell side effects
  (redirections, `mv`, `rm`) are invisible to them; use `[observe]` for
  on-disk evidence. A file observation shows that a file changed, never who
  changed it.
- File watching can coalesce or miss notifications. Loss is counted when the
  OS reports it. Bursts above roughly 2,800 files per second overflowed the
  queue on the development machine.
- `tailflow-daemon dashboard` (and its `--help`) says a sign-in link is
  "valid 5 minutes", but the link expires after 60 seconds.
- The startup banner can print `observe 0 directories` before observation has
  started.
- The terminal UI depends on `lru` 0.12, which RUSTSEC-2026-0002 and
  RUSTSEC-2026-0253 flag as unsound. The fix is a `ratatui` upgrade planned
  for 0.4.x.
- The Linux ARM64 binary needs glibc 2.39 or newer (Ubuntu 24.04+, Debian
  13+), as v0.3.3's did. The Linux x64 binary is built on Ubuntu 22.04 and
  runs on glibc 2.35 and newer. musl is not supported.

See [limitations](https://github.com/thinkgrid-labs/tailflow/blob/main/docs/limitations.md)
for the full list of boundaries.

## Report a bug

Open an issue with the
[bug report template](https://github.com/thinkgrid-labs/tailflow/issues/new?template=bug_report.md)
and put `0.4.0-rc.1` in the title. Include:

- the output of `tailflow --version`;
- your OS, its architecture, and the agent and agent version;
- steps to reproduce; and
- relevant output from `tailflow-daemon` or `tailflow-daemon storage status`.

Logs can contain credentials and personal data, so redact them before you
post.
